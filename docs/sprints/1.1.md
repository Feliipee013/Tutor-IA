# Sprint 1.1 — O plantão da madrugada

Plano da sprint 1.1 da **situação-problema 1.1**: um protótipo de tutor que responde às Perguntas Frequentes de um curso EaD da Unopar, com tom acolhedor e didático, rodando sobre LLM local.

**Prazo: 1 de outubro de 2026. Equipe: 7 pessoas.** MVP com falhas iniciais é aceito; o que não é aceito é não entregar.

Este arquivo é a camada legível do plano. A camada executável são os issues no tracker, que carregam os critérios de aceitação completos. Quando divergirem, o plano aqui decide escopo; os issues decidem o trabalho de cada pessoa.

Issue pai: [#2 — Sprint 1.1 — O plantão da madrugada](https://github.com/Feliipee013/Tutor-IA/issues/2).
Board: [Tutor IA - KANBAN](https://github.com/users/Feliipee013/projects/3).

## O que esta sprint entrega

1. Um bot de Telegram que o Aluno conversa de ponta a ponta, sobre Ollama local.
2. O S.A.U. falando como tutor: identidade, tom, recusa de Atividade, Encaminhamento.
3. As 10 Perguntas-teste com o comportamento esperado de cada.
4. Duas métricas binárias: taxa de não-saber e taxa de recusa de Atividade.
5. O documento de limitações do modelo.

## O que esta sprint deliberadamente NÃO entrega

- **Nenhum conteúdo factual do curso.** Sem RAG, o S.A.U. sabe o tom, não sabe o conteúdo. Essa separação é o que dá linha de base para a 1.2.
- **Nenhum material real.** As Perguntas-teste são sintéticas, criadas pela equipe. A limitação é declarada na documentação, não escondida.

## Caminho crítico

```
#3  #4  #5  #6          <- quatro frentes abertas desde o primeiro dia
     \  |  |  /
      \ |  | /
       #7                <- único gargalo inicial
        |
       #8
      /  \
    #9    #10
     |      |
    #11    #12
      \    /
       #13
        |
       #14
```

A espinha serial tem sete saltos: **#7 → #8 → #9/#10 → #11/#12 → #13 → #14**. Com 7 pessoas, o que limita a sprint é o comprimento da cadeia, não a falta de ticket.

#3 (modelo) e #6 (as 10 Perguntas-teste) não dependem de ninguém e são os que mais rendem se começarem hoje: #3 é conteúdo de pesquisa, #6 é conteúdo puro, e os dois podem sair sem que exista uma linha de código no repositório.

**#11 é o primeiro a ser cortado.** Concorrência é o requisito mais legal do projeto e o menos avaliado pelo professor; se algo não couber, é ele.

## Decisões que governam esta sprint

- [`CONTEXT.md`](../../CONTEXT.md) — glossário do domínio. O vocabulário dos issues vem de lá.
- [ADR-0001 — concorrência do bot](../adr/0001-concorrencia-do-bot.md) — estado por conversa, semáforo de inferência, webhook em vez de long polling.
- O grafo de resposta é LangGraph, usado só no loop de resposta (classificar e rotear o turno). Fora dele, LangChain.

## Saída para a 1.2

A 1.2 é co-entrega: **mesma data, 1 de outubro**. Ela reaproveita três artefatos desta sprint, e por isso a 1.1 precisa entregá-los de forma que a 1.2 possa reexecutar sem refazer nada:

- o harness (#12), que roda a bateria de Perguntas-teste e grava os outputs crus;
- o conjunto de 10 Perguntas-teste (#6), que não muda depois de criado;
- as duas métricas (#13), que são a régua do "antes".
